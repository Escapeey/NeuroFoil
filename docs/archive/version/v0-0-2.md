# v0.0.2 · PC 穿刺端到端链路打通（合成 GT → 训练 → 评估 → 延迟）

> 版本号：`v0.0.2`（中版本：功能新增）
> 日期：2026-11-25
> 对应开发者日志：[`docs/archive/CHANGELOG.md`](../CHANGELOG.md)

## 改动原因

- 需求说明书 §6 要求的交付物 1（训练脚本）需要先验证「GT 渲染 → 训练 → 评估 → 延迟」端到端链路能否跑通，才能进入超参扫描与工作点选取。
- 首要风险（逐像素 MLP 在 512×512@60fps 下的算力是否可控）需要一版可运行的度量方式给出初步结论。

## 改动方案

- **方案 A**：GT 直接对接 Blender / holo-card-studio 真实渲染管线，训练网络复现真实镭射卡。
  - 优点：数据保真，可直接回答「网络能否拟合真实光栅效果」。
  - 缺点：当前机器无 NVIDIA GPU、PyPI 不可达（仅中国镜像可用），Blender 管线未就绪，会阻塞链路验证。
- **方案 B**：先用纯 NumPy 程序化渲染一套**自包含合成 GT**（四层效果：多层视差 + 镭射彩虹 + Voronoi 星光 + 金边）作占位，把端到端链路先跑起来；真实 Blender GT 留待后续对齐。
  - 优点：无外部依赖、可复现、快；正好覆盖需求 §2 的分层效果定义。

## 最终改动方案

- 采用方案 B。合成 GT 渲染器 `spike/gt_holo.py` 用透视相机射线 → 平面求交 → 后到前 alpha 合成，输出 (res, res, 4) RGBA 帧；视角约定 ±45°（θ 绕 X 俯仰、φ 绕 Y 偏航）。
- 冻结神经纹理架构落码 `spike/model.py`：4 通道特征贴图（H×W）+ MLP（8 入参 = 双线性采样的 4 特征 + 2 uv + 2 角度 → 每像素 RGBA），`grid_sample(align_corners=True)`，激活默认 SiLU。
- 配套脚本：`dataset.py`（角度归一化 / 采样 / npz 存取）、`metrics.py`（PSNR + SSIM）、`train.py`（Adam + MSE + 周期评估）、`latency.py`（FLOPs 解析 + CPU 墙钟 + 移动端 GPU 折算）、`make_dataset.py`、`sweep.py`（超参扫描产 CSV）、`preview.py`（GT 拼图目检）。
- 依赖固定于 `requirements.txt`（torch≥2.2 / numpy≥1.26 / Pillow≥10.0）。

## 改动结果

- 端到端链路跑通：合成 GT（60 训练帧 + 25 验证帧 @128²）→ 训练 → 评估 → 延迟测量，全程 CPU 可复现。
- Smoke test（feat=64, width=32，训练 2000 步，Adam，MSE）：
  - 最终 PSNR **19.15 dB**，SSIM **0.606**，train loss **0.0137**
  - 参数量 **17,860**，模型体积 **约 71 KB**
  - 512×512 单帧前向：CPU 实测 **33.68 ms**（≈27.75 fps，**不达** 60fps）；按移动端 GPU 400 GFLOPs 折算 **1.85 ms**（可达成，FLOPs/像素 = 2816）
- 初步回答风险 #1：逐像素 MLP 在**移动端 GPU 上有裕量**达成 60fps，但 **CPU 平台无法达成**——端侧落地需 GPU/NPU 或下采样 + 插值等折中。

## 遗留事项

- PSNR（19 dB）远低于 30 dB 目标：需跑完整超参扫描（`sweep.py`）并增加步数，必要时引入傅里叶位置编码提升高频细节拟合（文字 / 线稿）。
- size ↔ quality ↔ latency 曲线（交付物 3）尚未产出，工作点（模型体积预算）未定。
- PC 实时查看器（512×512@60fps，交付物 2）尚未开始。
- 真实 Blender GT 管线对齐未做，当前仅合成数据。
- 结论报告（交付物 4）待曲线产出后撰写。

## 风险点

- 小网络拟合文字 / 线稿等高频细节困难，30 dB / SSIM≥0.95 可能需更大特征贴图或位置编码，需在扫描中验证，避免体积失控。
- CPU 平台无法达 60fps，若 PC 查看器仅跑 CPU，会低于目标帧率——需在查看器阶段明确硬件前提或引入降采样策略。
