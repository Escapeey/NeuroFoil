# v0.0.3 · 项目结构重组（四段管线 + assets 资产目录）

> 版本号：`v0.0.3`（中版本：结构调整 / 功能新增）
> 日期：2026-11-26
> 对应开发者日志：[`docs/archive/CHANGELOG.md`](../CHANGELOG.md)

## 改动原因

- v0.0.2 的代码全平铺在单一 `spike/` 包里，GT 渲染、训练、评估、预览混在一起，
  随着「用 skill 产出真实卡 → 导出训练集 → 训练 → 对比」管线成型，职责边界需要显式化。
- 用户已安装 `holo-card-studio` skill（用户级，非工程内），需要一处专门承载
  「调用 skill 得到可用演示 HTML」的编排代码，并把 skill 的分层素材 / 产物纳入资产管理。
- 训练 / 推理 / 对比代码此前用写死的 `data/`、`outputs/` 路径，无法支持「多张卡」并存；
  需要统一的按卡片名组织的资产目录，代码只认卡片名、不写死路径。

## 改动方案

- **方案 A**：仅把 `spike/` 拆成几个子目录，路径仍写死。
  - 优点：改动小。缺点：不支持多卡、skill 资产无处安放，治标不治本。
- **方案 B**：按数据流拆成四个代码文件夹（card_studio → dataset_export → training → compare），
  新增 `assets/<CardName>/{source,studio_project,html,dataset,outputs}` 资产目录，
  用统一的 `CardLayout` 解析路径；GT 渲染分「真实分层（skill 素材）」与「合成占位」两路，
  由门面按资产可用性自动调度。
  - 优点：职责清晰、支持多卡、真实素材与占位素材共存、全链路无资产也能自检。

## 最终改动方案

- 采用方案 B。新结构：
  - `card_studio/`：`run_card_studio.py`（编排 source 素材 → 调 skill `run_pipeline.py` →
    收集 web 查看器到 `assets/<card>/html/`）、`card-config.template.json`、`README.md`。
  - `dataset_export/`：`layout.py`（`CardLayout` 路径解析）、`angles.py`（视角采样 + npz 存取）、
    `layer_render.py`（读四层 PNG + 深度，透视相机逐层视差合成 + foil/sparkle，真实 GT）、
    `synthetic_gt.py`（原 `spike/gt_holo.py`，合成占位卡）、`api.py`（auto|skill|synthetic 调度门面）、
    `export.py`（CLI：`--card` → `assets/<card>/dataset/{train,val}.npz`）。
  - `training/`：`model.py`、`pixel_dataset.py`（原 `dataset.py` 的逐像素采样部分）、
    `metrics.py`、`latency.py`、`train.py`、`sweep.py`；`train/sweep` 改为 `--card`，
    默认从 `assets/<card>/dataset` 读、向 `assets/<card>/outputs/<tag>` 写。
  - `compare/`：`preview.py`（GT 拼图，重写为走渲染门面）、`gt_vs_model.py`
    （原临时 `_show.py` 升级：从 `metrics.json` 恢复架构、GT vs 模型并排对比）。
- 跨包依赖单向无环：`training → dataset_export`、`compare → training + dataset_export`、
  `card_studio → dataset_export`。各文件夹为独立 Python 包，在仓库根用 `python -m <pkg>.<mod>` 运行。
- 删除旧 `spike/` 与临时 `_show.py`；`.gitignore` 增加 `*.npz`、`assets/*/{studio_project,dataset,html}/`、
  `torchinductor_*/`（`outputs/` 已覆盖 `assets/*/outputs/`）；`source/` 原始素材保留入库。
- 更新 `README.md`（管线图 + 新目录树 + 常用命令）与 `assets/README.md`。

## 改动结果

- 工程结构重组完成，四段管线职责清晰、支持多卡、真实 / 合成双渲染源共存。
- 纯结构调整，未改动模型架构与训练逻辑（`model.py` 等原样迁移），不引入新的训练 / 性能结论。
- 全链路命令统一为 `python -m card_studio.run_card_studio` / `dataset_export.export` /
  `training.train` / `compare.gt_vs_model`，均以 `--card` 驱动、读写 `assets/<card>/`。

## 遗留事项

- `layer_render.py`（真实分层渲染）尚无真实 skill 素材可跑通验证，待 `card_studio` 产出
  MegaDiancie 四层 PNG 后做一次端到端核对（视差方向、foil 强度、与 GLB 外观一致性）。
- 真实 GT 与 skill 的 GLB/web 查看器为「2D 分层 + 解析 foil」近似，非像素级对齐；
  若需高保真，后续可改为对 GLB 做多视角离屏渲染。
- 旧根级 `data/`、`outputs/`（spike 时期 scratch，已 gitignore）与新 `assets/<card>/` 并存，
  待确认后可清理。
- 交付物 2（PC 实时查看器）、交付物 3（完整 size↔quality↔latency 曲线 + 工作点）、
  交付物 4（结论报告）仍未完成；多层视差表达上限（v0.0.2 遗留）未解。

## 风险点

- 跨包 import 依赖仓库根在 `sys.path`（`python -m` 从根运行满足）；若改为安装式包或
  从子目录运行，需补 `pyproject.toml` / 包安装，否则 `import dataset_export` 会失败。
- `run_card_studio.py` 依赖 skill 本体路径与 Blender 环境；skill 升级或换机时
  `--skill-dir` / 依赖需相应调整，脚本已对缺素材 / 缺管线做提示但未做自动安装。
